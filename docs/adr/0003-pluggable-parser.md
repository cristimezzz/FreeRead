# ADR-0003：可插拔的 PDF 解析引擎

- 状态：提议（默认引擎待 M0 验证后确定）
- 日期：2026-10-17

## 背景

解析质量决定了重排、翻译、问答的上限。各解析引擎在版面检测、公式识别、表格还原、速度、硬件要求上差异很大，而且这个领域迭代很快。

## 候选引擎

| 引擎 | 特点 | 硬件 |
|---|---|---|
| MinerU | 版面、公式（LaTeX）、表格质量较高，对中文论文友好 | 建议 GPU |
| Docling | 结构化输出好，许可证宽松，CPU 可用 | CPU / GPU |
| Marker | 输出 Markdown，速度较快 | CPU / GPU |
| PyMuPDF（快速模式） | 只提取文本块和坐标，无公式识别 | CPU，秒级 |
| 云端 API | 质量高，无需本地 GPU；但文档内容离开本机 | 无 |
| GROBID（辅助） | 参考文献与元数据结构化 | 需 Java 服务 |

## 决定

定义统一的 `Parser` 接口和每个引擎专属的 `Normalizer`，所有引擎输出都转换为 Document IR。首批实现 PyMuPDF 快速模式（保证无 GPU 时可用）和一个高质量引擎。默认高质量引擎由 M0 评测决定：在评测集上比较块类型准确率、阅读顺序、公式质量和耗时。

## 后果

- 正面：可以随时替换或新增引擎，不影响上层功能；用户可以按文档选择引擎重新解析。
- 负面：要为每个引擎维护 Normalizer；不同引擎的 IR 细节可能存在差异，需要评测集持续回归。
- 跟进：保存引擎原始输出到 `raw/`，Normalizer 升级时可以无需重新解析直接重建 IR。注意各引擎及其模型权重的许可证条款，在分发前确认。
