# ADR-0013：MinerU API 并发与限流

- 状态：已定稿
- 日期：2026-11-26
- 修订：[ADR-0008](0008-remote-parsers.md) 的 API 并发策略

## 背景

两个远程解析引擎原先共用 8 个并发名额。MinerU 的提交限流在 PDF 上传之后触发，结果轮询和下载缺少统一额度。

## 备选方案

1. 继续共享 API 调度组，按并发上限和轮询间隔估算请求量。
2. 独立调度各 API 引擎，在发送 MinerU 请求时直接计数。

## 决定

采用方案 2。MinerU API 并发可设为 1–32，默认 8。Docling API 独立并发 8，本机继续使用共享的本机并发设置。降低并发上限时，调度器等待运行中的任务自然结束。

MinerU API 在同一 Core 进程内共享三项滚动限额。任意连续 60 秒内最多发起 50 次 PDF 上传、50 次解析提交和 1000 次结果请求。结果轮询与产物下载共用额度，重试和重定向按实际发起的请求计数，额度用完时等待。服务端复用已有文件和同机直接读取 PDF 均无需发送上传请求。

## 后果

MinerU API 的并发可以在线调整，各引擎分别领取任务。额度只覆盖当前 Core 进程，重启后重新计数。多个客户端共用服务时，服务端仍可按账号或服务实例执行自己的上限。
