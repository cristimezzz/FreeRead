# ADR-0002：本地优先，使用 SQLite + sqlite-vec 作为唯一数据库

- 状态：提议
- 日期：2026-10-17

## 背景

个人文献库规模通常在数百到数万篇之间，需要存储元数据、文档块、译文、总结、向量和知识图谱。用户希望数据私有、可备份、无需安装数据库服务。

## 备选方案

1. **SQLite（主库）+ sqlite-vec（向量）+ 关系表存图**：单文件，零运维。
2. SQLite + LanceDB（向量）：向量能力更强，但多一份存储。
3. SQLite + 独立图数据库（如 Neo4j）：需要后台服务，对桌面用户太重。
4. PostgreSQL + pgvector：能力全面但需要安装服务。

## 决定

选择方案 1。图谱用 `kg_entities` / `kg_relations` 两张表存储，查询时按需把子图加载进 NetworkX。向量检索通过 `VectorIndex` 接口访问，便于在数据量过大时切换到 LanceDB。

## 后果

- 正面：一个文件即全部数据（加上 documents 目录），备份迁移简单。
- 负面：大规模全库图遍历性能有限；当前 k ≤ 2 跳的查询在个人规模下足够。
- 跟进：在 1 万篇、约 100 万块的规模上压测向量检索延迟。（2026-10-18 测到 10 万 chunk：单篇分区检索 <1 ms，全库暴力扫描约 0.25 s，见 [M2 检索](../m2/README.md#测量)；百万级留到 M3 跨文献检索时处理。）
