# M3 问答树（单篇）

单篇问答从线性对话改为一棵问答树：每个回答都可以追问、重答或另起一支，选中回答里的文字可以就此追问。交互参考 ai.explore.poker 的卡片式对话（子卡片 = 深入，同级卡片 = 新话题，分支卡片 = 重做同一轮，点高亮词派生新卡片）。M2 的检索、上下文组装、引用校验都不变（见 [m2/qa.md](../m2/qa.md)）。

## 模型

一个节点是一问一答（`qa_nodes`），`parent_id` 组成树；一个对话可以有多个根。四种操作只是新节点挂的位置不同：

| 操作 | 父节点 | 问题 | 其他 |
|---|---|---|---|
| 追问 | X | 新问题 | — |
| 重答 | X 的父节点 | 与 X 相同 | 不使用 LLM 缓存（否则拿回同一个答案） |
| 另起 | X 的父节点（X 是根时为新话题） | 新问题 | — |
| 就此追问 | X | 新问题（预填「选段」是什么意思？） | `anchor = {"text": 选中的文字}` |

## 上下文

- 历史只取新节点的**祖先链**（最近 `HISTORY_TURNS=3` 轮，去掉引用标记、每个回答截 600 字），兄弟分支互不可见。
- 检索查询 = 问题 + 父节点问题 + 选段。
- 提示词 `qa_answer@2`：历史标为"此前这一支的对话"，有选段时写明"用户在上一回答中选中了这段文字并就此追问：「…」"。

## 接口

- `POST /qa/sessions/{id}/ask` 新增 `parent_id`（`null` 为新的根）、`anchor`（≤500 字）、`regenerate`。`parent_id` 不在该对话里时返回 `error{code: bad_request}`。前端总是显式传 `parent_id`。
- `DELETE /qa/nodes/{node_id}`：删除节点及其整棵子树（外键是 `ON DELETE SET NULL`，所以由服务层收集子树一起删）。
- `GET /qa/sessions/{id}` 仍返回按创建时间排好的扁平节点列表，前端自己建树（`features/qa/tree.ts`）。

## 界面

- 侧栏顶部是一条矮画布（`QaCanvas.tsx`）：整齐树布局（叶子各占一列、父节点居中，自上而下），拖动平移、滚轮缩放，点卡片切到那一支最新的叶子。当前路径用墨色，当前节点用强调色。可以隐藏，也可以展开铺满阅读区（与图谱云图同一做法，Esc 收起）。没有引入 React Flow：节点不多，手写布局更贴合 ADR-0007 的样式。
- 阅读区只显示根到当前节点的路径；有兄弟分支的一轮显示 `‹ 2/3 ›` 切换。悬停一轮显示 追问 · 重答 · 另起 · 删除分支。
- 在回答里选中文字浮出"就此追问"；父回答里子节点的选段加强调色下划线，点它进入那一支（`anchors.ts` 在去掉引用标记的文本上按词匹配）。
- 输入框上方写明问题会挂在哪：追问 ›「…」/ 另起 / 就此追问 / 新话题。

## 迁移

`0011_qa_tree`：`qa_nodes` 加 `anchor`（JSON，可空）和索引 `(session_id, parent_id)`。M2 的对话本来就是一条链（`parent_id` 指向上一轮），升级时把每个对话里除第一轮外 `parent_id` 为空的轮次接到前一轮上，老对话显示为单支的树。

## 以后

固定原文片段（`pinned_blocks`）、拖入图谱实体（`subgraph`）、手动摆放节点（`position`）、祖先链过长时做摘要，都还没做。
