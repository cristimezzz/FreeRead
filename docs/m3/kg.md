## 结论速览

| 项目 | 结果 |
|---|---|
| 范围 | **每篇论文一张图**，实体不跨文档合并（用户决定：不需要多论文图谱） |
| 抽取 | 后台任务 `kg_extract`：按章节组（约 2500 token）逐组调用模型，一篇内并发 2；实体 6 类、关系 7 类（固定 schema） |
| 精简 | 提示词只要核心实体（每组最多 10 个）；合并后再按重要性精简：去掉没有关系且只出现一次的，Concept 最多 15 个，全篇最多 60 个 |
| 出处 | 每条关系必须带本组的出处块；摘句不在原文里就清空并降 confidence；`achieves` 的数值必须在出处块里出现，否则丢弃整条 |
| 重新解析 | 提及和关系的出处块按块映射迁移；映射不上的关系标"出处已失效" |
| 触发 | 阅读器"图谱"面板手动抽取；设置里"建立语义索引后自动抽取图谱"（默认关） |
| 模型路由 | `kg_extract` 未单独配置时沿用总结的服务（再回退到翻译）；首次发送前需要确认 |
| 界面 | 阅读器侧栏"图谱"：3D 链接云图（three.js，懒加载），可展开铺满阅读区；重要关系和悬停节点的全部关系直接标在连线上；类型图例可开关，点节点 / 关系名看详情和出处并跳回原文 |

## 设计

### 数据（迁移 `0010_kg_per_doc`）

- `kg_entities`：属于一篇文档（`doc_id`），别名存成 JSON 列，`score = 2 × 关系数 + 提及块数`。
- `kg_mentions`：实体在哪个块里出现，记原文写法。
- `kg_relations`：出处块 `source_block_id` 必填；`status` 为 `ok` / `stale`。
- 删除文档时它的图级联删除。`0010` 删掉了 `0008` / `0009` 的别名表、`kg_distinct`、合并建议和实体向量，旧图谱清空（`kg_status` 回到 `pending`），需要重新抽取。

### 名称归一化（`domain/kg/normalize.py`）

NFKC、casefold，希腊字母写成拉丁名，去掉空白、连字符、下划线和撇号，去掉首尾标点和英文所有格。点保留（`GPT-3.5` ≠ `GPT-35`），不做词干化。`全称 (缩写)` 拆成两个别名。用于文档内合并各组的实体。

### 抽取与校验（`domain/kg/extract.py`、`services/kg.py`）

- 分组复用总结的 `group_blocks`，输入复用 `source_blocks`（页眉页脚等不发送）。标题块只作小标题，不能被引用。
- 每组回复解析失败时不走缓存重试一次；单组失败不影响其他组，全部失败时任务失败，错误信息带第一个失败原因。
- 服务商返回 401 / 402 / 403（密钥无效、余额不足、无权限）时不再调用剩下的组，整个任务失败并显示服务商的说明（如 `HTTP 402: Insufficient Balance`），不写入部分结果。
- 实体的提及：模型给出的块，加上别名在本组块里实际出现的位置（拉丁文字按词边界，`BERT` 不命中 `RoBERTa`）。既没有提及也没有关系的实体丢弃。
- 数值核对按数值比较：`85.30` = `85.3`，`1,234` = `1234`；名称里的数字（`ResNet-50` 的 50、`F1` 的 1）不算，紧挨中文的数字（"为66.5h"、"增加41倍"）算。显示用模型给的原写法（`<50`、`0.07 ± 0.05`），核对用其中第一个数。
- 摘句核对忽略大小写、所有空白（PDF 换行会在中文里插空格、在英文里吞空格）和连字符写法；用省略号截断的摘句各段按顺序都找得到也算。
- 同一篇内，同类型且任一别名归一化相同的实体合并；关系按 (src, dst, type, block) 去重。
- 精简（`extract.prune`）：按 score 排序，去掉没有关系且只出现一次的实体，Concept 最多 15 个、总数最多 60 个；被去掉的实体的关系一并去掉，数量记在任务信息里（"略去 N 个次要实体"）。
- 写入在一个事务里：删除该文档原有的图，写入新的。

### 3D 云图（`apps/desktop/src/features/kg/`）

第一版用 3d-force-graph：标签是世界坐标大小的文字精灵，镜头一远就看不清，关系名只在悬停时出现，侧栏里整张图也太小。第二版直接用 three.js 重写：

- 布局（`layout.ts`，纯函数）：d3-force-3d 同步跑 300 步得到静态布局（连线距离 90、斥力 −450、碰撞半径 = 球半径 + 12，另有向中心的弱引力，把不相连的小块拉回来）。初始位置按 id 哈希放在球面上，同一张图每次布局相同；筛选类型、展开 / 收起时位置不变，画面也不抖。
- 绘制（`KgScene.ts`，打开图谱时 `import()`，单独的 chunk）：
  - 节点：球体，颜色取 `--kg-method` 等令牌（`app/theme.ts` 的 `KG_COLORS`，浅色 / 深色各一组，用 dataviz 校验脚本检查过亮度带、彩度和相邻色在色觉障碍下的区分度），半径 4 + 2.2·√score（上限 14）。节点名是 CSS2D 的 DOM 标签（带类型色点，12px），远近都清楚；离镜头远的变淡。
  - 关系：`Line2` 按像素宽度画（平时 1.5px，突出时 3px），线型区分类别：实线 = 提出 / 改进 / 取得，虚线 = 使用 / 属于 / 评估于，点线 = 对比（面板图例下有说明）；出处失效的变淡；目标端有圆锥箭头。
  - 同一对实体之间同类型的关系（出自不同的块）合成一条线，标签写"使用 ×3"，详情卡列出全部出处；数值结果各自一条。
  - 关系名标签在连线中点，是可以点击（也可以 Tab 选中）的按钮。平时只标重要节点之间的关系（两端都在前 12 个重要节点里），数量随画布大小在 6–25 条之间；节点名同样随画布大小在 8–20 个之间。
  - 悬停或选中一个节点时，它和一跳邻居保持原色、其余变淡，并标出它的全部关系名；从节点移到它的关系名上时悬停保持，可以直接点。
  - 去重叠：每帧按优先级（焦点 / 选中 → 突出的关系 → 最重要的 6 个节点名 → 重要关系名 → 其余节点名）摆放文字，和已摆放的重叠的先藏起来。
  - 镜头按包围球直接计算（全貌忽略最远的 10% 节点），不依赖模拟何时停下。点节点镜头补间到它和邻居，点关系补间到两端，点空白退回全貌。只在镜头移动、补间、悬停变化时渲染。系统开启"减少动态效果"时不补间、不用阻尼。
- 展开（`ReaderView.tsx` + `KgPanel.tsx`）：侧栏头部的"展开"按钮把云图（`createPortal`）铺到阅读区上（覆盖原版和重排，侧栏的图例和详情卡不动），Esc 或"收起"恢复；展开时点出处会先收起再跳到原文；关闭图谱面板时一并收起。
- 面板（`KgPanel.tsx`）：抽取 / 重新抽取按钮与进度、类型图例（点一下隐藏该类，连线一起隐藏）、线型说明、云图、详情卡。详情卡：实体的类型、描述、别名、出处编号（点击跳到原文块并高亮 PDF）、相连的关系；关系的两端、数值、摘句和出处。
- 主题切换（`data-theme` 变化）时重新上色；文字标签用 CSS 令牌，自动跟随。没有 WebGL 时显示一行提示。

### 提示词

- `kg_extract@3`：输入标题、组标题和 `[b_xxxx] 文本` 行；输出 `{"entities": [{id, type, name, aliases, description, block_ids}], "relations": [{src, dst, type, block_id, evidence, attrs, confidence}]}`。只抽取读者理解这篇论文必须知道的实体（每组最多 10 个，不要背景里一笔带过的方法、通用术语、人名机构）；name 不翻译、关系只引用给出的块号、摘句逐字抄写、`achieves` 的数值原样抄写（保留 <、±、%），只记本文方法和主要基线的关键结果；幅度、倍数、消融差值要在 setting 里写明。
- v3 去掉了 Claim 实体和 contradicts 关系（单篇图里很少有用，名字是整句话，在云图里不可读）。

### 接口

- `POST /documents/{doc_id}/kg/extract` → 202 `JobOut`；同一文档已有任务时返回它；模型不可用时 409，`detail = {code, message, provider_id}`。
- `GET /documents/{doc_id}/kg` → `{doc_id, kg_status, entities, relations}`：实体按 score 降序，含别名、出现的块和 score；关系含两端名称、attrs、出处块、摘句和 status。
- `DocumentOut.kg_status`：`pending / extracting / ready / failed`；已有图谱时重新抽取失败会回到 `ready`。

## 历史：跨文档消歧（2026-10-20 ～ 10-21，已删除）

第一版（迁移 `0008` / `0009`）实体全库共享：别名精确命中自动合并，内置 e5 嵌入找同类候选（余弦 ≥ 0.86），`kg_resolve` 让模型成对判定，判为同一个的作为"可能重复"让用户确认；另有改名、合并、拆分、删除关系。下面的测量和评测是那时做的。数值核对、摘句核对和提示词 v2 的结论仍然适用；消歧部分随功能一起删除（用户决定不需要多论文图谱、只保留每篇最重要的信息）。

### 嵌入相似度测量

用内置 multilingual-e5-small 对 22 对手写名称（10 对同一个、12 对不是同一个）算余弦：同一个 0.864–0.978，不是同一个 0.941–0.987，两段大面积重叠（如 BERT-base / BERT-large 0.966、WMT14 En-De / En-Fr 0.987），按相似度直接合并会大量误合并。

### DeepSeek 评测

`scripts/m3_kg_eval.py`（当时的版本），deepseek-chat（`kg_extract@1` / `kg_resolve@1`），评测集 31 篇（PyMuPDF 快速解析），内置 e5 找候选，4 篇并发、每篇 3 组并发。

| 项目 | 结果 |
|---|---|
| 文档 | 29 / 31 篇；另 2 篇是扫描版，没有文字层（任务失败："文档里没有可抽取图谱的正文"） |
| 耗时 / 调用 | 200 s；342 次调用，输入 86.6 万 / 输出 60.4 万 token |
| 规模 | 3565 个实体、3608 条关系（uses 1376、part_of 1139、evaluated_on 251、achieves 222…）；308 个实体出现在 2 篇以上 |
| **出处块存在** | **3608 / 3608** |
| 丢弃 | 数值核对不上 170、出处不在本组 9、关系不合法 91、实体不合法或无出处 45；失败的组 0 |
| 摘句 | 948 条核对不上被清空（26%） |
| 消歧 | 嵌入候选送判定 2696 对，判为同一个 119 对 |

人工抽检（逐篇 `eval-out/m3-kg/<doc_id>.md`）发现的问题和处理：

1. **紧挨中文的数字核对不上**（核对的 bug）：数字前一个字符按 `\w` 判断，中文也算 `\w`，"为66.5h""在68%""增加41倍"都找不到。改为只看拉丁字母和数字。
2. **摘句误判**：PDF 换行在中文里插入空格（"同义保 真度"），英文里又会吞掉空格（"BD Canto II" → "BDCantoII"）。改为去掉所有空白、统一连字符后比较，并接受省略号截断。真正改写过的摘句（如把摘要改述成一句话）仍然清空。
3. **非数值的 value**：被丢弃的 170 条里大约九成 value 是"shortened""更高""显著相关"之类的文字，丢弃是对的；提示词 v2 要求这类结果不写成 achieves。
4. **比较符号丢失**：`均值<50` 显示成 `= 50`。改为显示模型给的原写法。
5. **差值当成绩**："去掉 BFD 后准确率下降 0.4 GDT"被记成 `AlphaFold · GDT = 0.4`。提示词 v2 要求幅度、倍数、消融差值在 setting 里写明。
6. **判定把上下位 / 相关概念当成同一个**：119 对"是"里大约五分之一不对，几乎都是上下位或相关——HEK293T 细胞 ↔ HEK-293、深度生成模型 ↔ deep learning、CD19 CAR 阳性率 ↔ CD19 CARs、immunity-for-intelligence trade-off ↔ immunogenicity。跨语言的同义合并大多正确（流式细胞术 ↔ Flow cytometry、t检验 ↔ Student's t test）。`kg_resolve@2` 改成五选一的关系类别，只有 same 合并。

修正 1、2 后用缓存的 v1 回复离线重放（不联网）：保留的数值结果 222 → 262；仍因核对不上丢弃 128 条，其中真正是数值的只有 12 条（多为模型引错了块）；摘句清空 984 → 512 条（保留摘句的关系 87%）。数值结果抽检（AlphaFold、CodonTransformer 等）：方法、指标、数据集和数值与原文一致，出处跳转正确。

第一次复测 v2（2026-10-21）不能和 v1 直接比较，只作参考：

- 换了模型：deepseek-flash（v1 是 deepseek-chat）。每组输出约 9000 token（v1 约 1800），单次调用中位 34 s、22 次超过 60 s；35 个组失败、1 篇整篇失败，失败原因没有记录下来（当时警告只打在终端里）。
- 数据目录沿用了 v1：v1 的实体还在库里，消歧时和它们比较；整篇失败的那篇显示的还是 v1 的图；报告里的调用数混进了 v1 和离线重放。评测脚本已改为每次运行先清空图谱、只统计本次调用、警告写进 `run.log`。
- 可以看出的趋势：数值核对丢弃 22 条（v1 170），摘句清空 142 条，achieves 460 条；判定为同一个的 47 对里约 4–6 对可疑（v1 约五分之一），但明显的同义也被判成不同，如 HMMER v.3.3 ↔ HMMER v3.3、Cα r.m.s.d. at 95% coverage ↔ r.m.s.d.95、蛋白表达 ↔ protein expression、运行时间 ↔ runtime。

需要用 deepseek-chat 重跑一次，才能分清提示词和模型各自的影响。

第二次复测（deepseek-chat）一开始就遇到账户余额不足（HTTP 402），只有 3 组成功，没有结论。它暴露的问题已修正：之前所有组失败时任务报"模型没有返回可解析的图谱"，掩盖了真实原因；现在遇到 401 / 402 / 403 立即停止并报服务商的错误。

第三次复测（deepseek-chat，v2 提示词）：29 / 31 篇，但 DeepSeek 当天限流严重，79 个组失败（429 限流 371 次、读超时 55 次；同样并发下 v1 没有失败），所以总量（实体、关系、数值结果数）不能和 v1 比，只看成功部分的质量：

- **数值结果明显变好**：保留比较符号和范围（`>5,000`、`∼0.716`、`4.57 ± 0.39%`），倍数写明相对谁（"relative to Benchmark-FL2 in HepG2 cells"），抽检里没有文字 value。主体偶尔不理想（如把"median of 120 phospho-Ser"当成实体）。出处块存在 1223 / 1223。
- **判定没有变好**：判为同一个的 34 对里约 12–14 对不对（v1 约五分之一）：Pearson r 和 Spearman's r 都被并进了 "R"，hQTL ↔ haQTL analysis，脂质多聚复合物 ↔ LNP encapsulation，杰卡德指数 / 序列相似性 ↔ 密码子级匹配率。五选一的类别没有让 deepseek-chat 更谨慎。

结论：数值抽取的 v2 提示词保留；模型成对判定在两个模型、两版提示词上的误合并都在 10%–40%，自动合并不可靠，需要改策略（见遗留）。

## 验证

- `core`：`tests/test_kg.py` 11 个测试：
  - 归一化与缩写拆分；数值解析与核对；摘句核对；
  - 单组校验：越组块号、未知类型、端点不存在、找不到的数值、编造的摘句；
  - 精简：没有关系且只出现一次的去掉，Concept 和总数上限，被去掉实体的关系一起去掉；
  - 抽取任务：实体、提及、关系入库，出处块都存在，结束信息（含"略去 N 个次要实体"），重新抽取整体替换；
  - 两篇文档里同名实体是各自的节点，删除文档时它的图级联删除；
  - 服务商返回 402 时任务失败并报服务商的错误，不再继续调用；
  - 重新解析时出处迁移，映射不上的标 stale；
  - 自动抽取开关、隐私确认、排队去重；API 状态码，旧的全库实体接口已不存在。
- 迁移：`0010` 升级后再降到 `0009`、再升级，表结构正确；已有文档的 `kg_status` 回到 `pending`。
- 前端：`tsc`、`vitest` 通过：`toCloudData` 的映射、类型隐藏和同类关系合并；每个类型都有浅色 / 深色令牌；布局确定、无 NaN、相连节点更近；关系名的默认上限与焦点规则；包围球忽略离群点。`vite build` 里 three 是单独的 chunk（`KgScene`，593 KB / gzip 149 KB；第一版 3d-force-graph 约 1.4 MB）。
