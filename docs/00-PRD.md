# FreeRead 产品需求文档（PRD）

- 版本：0.1（草案）
- 更新日期：2026-10-17

## 1. 产品定位

FreeRead 是一款**本地优先**的学术文献阅读工具。它从 Zotero 导入文献库，把 PDF 解析成结构化文档后**自动重排**，并借助大语言模型提供**翻译**、**总结**和**图状结构问答**。

一句话：让研究者用自己熟悉的语言、舒适的版式读论文，并能跨论文提问和追溯原文。

## 2. 目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 研究生 / 科研人员（主要） | 已用 Zotero 管理文献；大量阅读英文论文 | 读得快、读得懂、能追溯 |
| 工程师 / 技术调研者 | 阶段性集中阅读某一领域 | 快速获得领域全貌、对比方法 |
| 非英语母语读者 | 英文阅读吃力 | 高质量、保留公式和术语的翻译 |

## 3. 核心场景（用户故事）

1. **导入**：作为 Zotero 用户，我希望一键导入我的文献库（或某个分类），无需手动拖文件。
2. **重排阅读**：作为在笔记本或平板上读双栏论文的人，我希望看到单栏、可调字号、公式清晰的重排版本，并能随时切回原版 PDF 的对应位置。
3. **翻译**：我希望以段落对照方式阅读译文，公式、引用、术语不被翻错；术语可以由我统一指定。
4. **总结**：拿到一篇新论文，我希望一分钟内看到结构化总结（问题、方法、实验、结论、局限），每条结论都能点击跳回原文。
5. **单篇问答**：我希望针对当前论文提问，答案附带原文引用。
6. **跨文献问答**：我希望问"这个分类里哪些方法在 ImageNet 上比 X 更好？"，系统基于知识图谱和原文给出有出处的回答。
7. **问答画布**：我希望在画布上从任意回答分叉追问，把整个探索过程保存为一棵问答树。

## 4. 功能清单与优先级

优先级：P0 = MVP 必须；P1 = 第一个正式版；P2 = 之后。

### 4.1 文献库（Library）
| 功能 | 优先级 |
|---|---|
| 通过 Zotero 7 本地 API 导入条目、分类、标签、PDF 附件 | P0 |
| 读取 `zotero.sqlite` 快照导入（Zotero 未运行时） | P1 |
| 通过 Zotero Web API 同步 | P2 |
| 增量同步（基于 version / dateModified） | P1 |
| 手动拖入本地 PDF | P0 |
| 将总结、笔记写回 Zotero（仅 Web API / 插件） | P2 |

### 4.2 解析与重排阅读（Reader）
| 功能 | 优先级 |
|---|---|
| PDF → Document IR 解析（段落、标题、公式、表格、图、图注、参考文献） | P0 |
| 重排视图：单栏、字号 / 行宽 / 主题可调，公式用 KaTeX 渲染 | P0 |
| 原版 PDF 视图（pdf.js） | P0 |
| 重排 ⇄ 原版双向定位与高亮 | P0 |
| 多解析引擎可切换（本地高质量 / 快速降级 / 云端） | P1 |
| 按页重新解析、手动修正块类型 | P2 |
| 高亮与批注（存于本地，可导出） | P1 |

### 4.3 翻译（Translate）
| 功能 | 优先级 |
|---|---|
| 按块翻译，流式输出；优先翻译可视区域 | P0 |
| 对照 / 交替 / 仅译文三种显示 | P0 |
| 公式、引用、行内代码占位保护 | P0 |
| 术语表（自动抽取 + 用户编辑） | P1 |
| 单段重新翻译、切换模型 | P1 |
| 整篇后台批量翻译 | P1 |

### 4.4 AI 总结（Summary）
| 功能 | 优先级 |
|---|---|
| 分层总结（章节 → 全文），结构化模板 | P1 |
| 每条结论附 block 引用，可点击跳转 | P1 |
| 自定义总结模板 | P2 |
| 分类级综述（多篇论文对比表） | P2 |

### 4.5 图状结构问答（Graph QA）
| 功能 | 优先级 |
|---|---|
| 单篇论文 RAG 问答，答案带引用 | P1 |
| 知识图谱抽取（实体 + 关系，带出处） | P2 |
| 跨文献混合检索问答（向量 + 图扩展） | P2 |
| 图谱可视化浏览 | P2 |
| 问答画布：问答树、分叉追问、固定原文片段 | P2 |

### 4.6 设置与通用
| 功能 | 优先级 |
|---|---|
| LLM 提供方配置（OpenAI 兼容 / Claude / Ollama），按任务选模型 | P0 |
| API Key 存于系统钥匙串 | P0 |
| Token 用量与费用统计 | P1 |
| 导出 Markdown（含译文、总结） | P1 |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 隐私 | 默认所有数据保存在本地；只有用户配置的 LLM / 云解析服务会收到文本，且首次使用前明确提示 |
| 性能 | 打开已解析文献 < 1 s；可视区域首段译文开始流式输出 < 3 s（取决于模型） |
| 解析 | 20 页论文本地解析 < 2 min（有 GPU）；解析在后台进行，不阻塞阅读原版 |
| 可靠性 | 长任务可断点续跑；应用崩溃不丢失已完成的翻译 / 总结 |
| 安全 | **绝不写入用户的 `zotero.sqlite`**；只读快照 |
| 平台 | Windows 10+ 优先，其次 macOS、Linux |
| 成本 | 所有 LLM 结果缓存；同一内容不重复计费 |

## 6. 非目标（当前版本不做）

- 不替代 Zotero 的文献管理功能（引用格式化、Word 插件等）。
- 不做多人协作和云端账号体系。
- 不做移动端。
- 不训练或微调模型。

## 7. 成功指标

- 评测集（见架构文档"测试与评测"）上的解析结构准确率 ≥ 90%（块类型 + 阅读顺序）。
- 翻译中公式 / 引用的占位还原成功率 ≥ 99.5%。
- 总结中带引用的结论比例 ≥ 90%，人工抽检忠实度 ≥ 95%。
