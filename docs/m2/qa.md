## 结论速览

| 项目 | 结果 |
|---|---|
| 入口 | 阅读器右侧"问答"面板（和搜索、总结共用位置）。每篇论文可以开多个对话：新建、切换、删除；追问时带上本对话最近 3 轮 |
| 流程 | 混合检索 → 加邻块和摘要组成上下文 → 流式生成（要求用 `[b_xxxx]` 标出处）→ 引用校验 → 存库 |
| 引用 | 答案里的编号就地规范化；文档里不存在的编号从正文中删除。所以展示出来的引用 100% 存在，点击后定位到重排视图和原版 |
| 没有语义索引 | 照常可用，用关键词检索加摘要和开头段落作为上下文；面板提示去 设置 › 检索 下载嵌入模型 |
| 路由与隐私 | 未单独设置时依次沿用总结、翻译的服务（设置 › 问答 › "与总结相同"）；首次发送前弹确认框，和翻译、总结共用同意记录 |
| 验收（引用 100% 指向存在的块） | 机制上保证：校验后只剩存在的编号。真实模型评测脚本已就绪，**待你配置 Key 后运行** |

## 设计

### 上下文（`domain/qa/context.py`）

- 检索词是当前问题；追问时再拼上上一轮的问题（"那它的局限呢？"这类问题单独检索不到东西）。不额外调用 LLM 做查询改写。
- `SearchService.search_document(k=12)` 返回按 RRF 排序的块。依名次加入命中块，以及它在同一章节内的前后邻块，因为检索单元常常只是半个论点。
- 摘要块总是先放，帮模型了解全文在讲什么，但最多占预算的 1/4。
- 预算约 4000 token（`approx_tokens`），超出就停。输出按阅读顺序，章节变化时加一行章节标题，标题不带编号。
- 检索没有命中时，退回到论文开头的段落。
- 块文本复用总结的 `source_blocks`：占位符已展开，页眉页脚等装饰块已排除。

### 生成（`core/prompts/qa_answer.yaml`）

- 只依据给出的原文、用目标语言回答，每个论断后紧跟 `[b_0012]`，只能使用给出的编号。
- 原文里找不到答案时直说"论文中没有找到相关内容"，可以提相近的信息，但不猜测。
- 对话历史：最近 3 轮，答案去掉引用标记、各截到 600 字，内联进 user 模板。历史里的编号不再给模型，免得它引用这次没给出的块。
- 用 `gateway.stream` 流式输出。相同问题、相同上下文的再次提问命中缓存，一次返回全文。

### 校验（`domain/qa/citations.py`）

- `validate_answer` 识别 `[b_12]`、`【b_0012】`、`[b_1, b_2]`、`(d_…#b_0012)` 等写法，就地改写为 `[b_0012][b_0013]`。文档里不存在的编号连同标记一起删除，计入 `stats.invalid_ids`。
- 存在于文档、但不在这次上下文里的编号保留，计入 `stats.out_of_context`。这种情况多半是模型从对话历史里"记得"的，引用本身仍然有效。
- 没有任何引用的答案标 `untraced`，界面显示"未找到依据"。

### 流式与校验的配合

SSE 依次发出：
- `context`（这次送给模型的块和检索方式）；
- 多个 `delta`（未校验的原文；前端隐藏所有引用标记和末尾没写完的标记，只显示文字）；
- `answer`（校验后的结果，前端用它替换流式文本，并渲染编号标签）。

断开连接即停止生成，这一轮不保存。

### 存储与重新解析

- `qa_sessions`、`qa_nodes`（迁移 0004，见[数据模型 §7](../03-data-model.md)）。`parent_id` 指向上一轮；M3 画布的 `pinned_blocks` / `subgraph` / `position` 到时再加。
- 重新解析时与译文、总结在同一事务里改写答案标记和 `citations`（`migrate_qa`）。映射不上的标记删除，这一轮标 `stale`，面板提示原文已重新解析。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / POST | `/documents/{doc_id}/qa/sessions` | 对话列表（最近活动在前）/ 新建 |
| GET / DELETE | `/qa/sessions/{id}` | 对话详情（各轮）/ 删除 |
| POST | `/qa/sessions/{id}/ask` | `{question, lang?}`，SSE：`context` / `delta` / `answer` / `error` / `done` |

## 评测（`scripts/m2_qa_eval.py`）

- 问题集 `core/tests/fixtures/pdfs/qa_questions.yaml`：
  - 5 个通用问题每篇都问：研究问题、数据、关键数值、局限，外加一个英文问题；
  - 1 个陷阱题（"在哪些城市开展了问卷调查？"），用来检查模型会不会编造；
  - 也可以按 doc_id 追加专门的问题。
- 每个问题开一个新对话。统计：
  - 展示引用有效率（验收项，应为 100%）；
  - 模型原始编号的有效率；
  - 有引用的回答比例；
  - 引用不在上下文里的比例；
  - 陷阱题没有编造的比例。
- 每篇生成一份对照稿 `eval-out/m2-qa/<doc_id>.md`，列出问题、回答和引用的原文，供人工抽检忠实度。
- 参数与总结评测相同：`--jobs`、`--record` / `--replay`、`--extra-body`。两个脚本共用 `freeread/eval/runner.py`。`--fake` 默认输出到 `eval-out/m2-qa-fake/`，不会覆盖真实结果。

```bash
cd core
set FREEREAD_EVAL_API_KEY=sk-...
.venv/Scripts/python ../scripts/m2_qa_eval.py --base-url https://api.deepseek.com/v1 --model deepseek-chat --record ../eval-out/m2-qa/replies.json
```

## 验证

- `core`：198 个测试通过。新增 `tests/test_qa.py` 共 7 个，覆盖：
  - 引用校验的各种写法和无效编号删除；
  - 上下文的邻块、摘要、预算、阅读顺序和无命中时的回退；
  - 服务的事件顺序、流式原文与校验结果、历史串联、会话标题、级联删除、路由回退、隐私确认、无依据回答；
  - 重新解析后引用迁移与 `stale`；
  - API 与评测函数。
- 前端：`tsc`、`vitest` 通过。
- 浏览器模式（sidecar、Vite、本地 OpenAI 兼容 mock，问答请求流式返回），在评测集的 mRNA 论文上：
  - 提问 → 弹出"发送文档内容进行问答？"→ 允许 → 流式显示，没写完的标记不露出 → 校验后 2 个编号标签（编造的 b_9999 已删）；
  - 点标签后重排视图和原版定位到 b_0008；
  - 追问进入同一对话（后端 1 个对话 2 轮）；刷新后对话和各轮仍在；
  - 新建、提问后自动切到新对话、切换、删除都正常；控制台没有错误。
- 顺带修了共用的 `Select` 组件：选项异步加载时（如对话列表），Material select 的显示文字不更新。现在选项或值变化后会按值重新选中并补上显示文字。设置页所有下拉框复查过，显示正常。
