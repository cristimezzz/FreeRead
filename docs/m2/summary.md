## 设计

### Map：分组（`domain/summary/grouping.py`）

- 每个块沿 section 的 `parent_id` 找到根章节（通常是一级标题），按根章节分组。第一个标题之前的块（论文标题、摘要）单独成一组"标题与摘要"。
- 只送可检索的块（可翻译类型和表格），正文用 `block_plain_text` 展开占位符。参考文献、作者信息、公式块不送。标题块只作为组内的小标题行，不带编号，避免模型引用标题。
- 相邻小组合并到约 3000 token，超过 6000 token 的组按块边界切开（标题加"（续）"）。评测集里一篇 14 页的英文论文切成 9 组，28 页的中文译本切成 11 组。
- 每个块在提示词里写成 `[b_0012] 文本`，要求模型原样抄写编号。
- 送 Map 前排除页面装饰块（见下一节）。

### 页面装饰块（`domain/summary/decoration.py`）

快速模式只丢弃页面上下 6% 内的短文本，侧边栏的下载水印、较长的期刊信息行、版权行会以 paragraph 进入 IR，被模型当依据引用（评测集旧结果里 Grubert 那篇首页的期刊信息行被引用了 3 次）。IR 没有标记它们的字段（`flags` 里没有对应取值，blocks 表也不存 flags），所以总结时按锚点和文本判断，满足其一即排除：

1. **跨页重复的边缘块**：块的每个锚点都在页面边缘带（上下 10%、左右 8%），且归一化文本（小写、数字串统一成 `#`、去掉空白和控制字符）在至少 2 个不同页面的边缘带出现。页眉、页脚、页码不同的卷期行、PNAS 侧边的学科标签都由这条覆盖。
2. **固定样板**（≤ 400 字符）：`Downloaded from <URL>`、`All rights reserved`、`©` / `ª` / `Copyright` 加年份、`作者 et al., 2015, Cell 162, 1051–1065` 式期刊引用行、`Volume 18, Number 2` 式卷期行、`(legend continued on next page)`。
3. **边缘带里的 DOI 行**：块在边缘带，去掉 DOI / URL 后剩下的文字权重 ≤ 20（拉丁字母记 1，汉字记 3），如首页角上的 `doi:10.1038/… Published online 9 May 2016`。限定边缘带，避免误伤正文里"代码见 https://…"这类短句；URL 只匹配 ASCII 字符，因为中文行里 URL 后常紧跟汉字。

只对 paragraph / footnote / other 生效，标题、摘要、作者信息、章节标题、图注、表格都不动；被排除的块在分组输入里文本置空，不进入任何组，所以模型看不到它们的编号。

评测集 31 篇（快速模式）共排除 170 / 7227 个块，逐条看过：几乎都是下载水印、页眉页脚、版权行、期刊信息行、"续下页"提示。另有 16 个是图内文字（`P < 0.0001`、`Marker`、坐标轴标签），它们恰好在页面边缘且跨页重复；它们本来就不是正文，排除了没有坏处。没有正文、图注或首页标题被排除。验证时发现一条中文正文（`（https://doi.org/…），并可免费用于学术和研究用`）被第 3 条误伤，已按上面的汉字权重和 ASCII URL 修正。

### 提示词（`core/prompts/`）

- `summarize_map@1`：只依据给出的内容提炼 3–8 个要点，每条给 1–3 个块编号，只输出 `{"points": [...]}`。
- `summarize_reduce@1`：输入各组要点（要点后面带编号）和模板的小节说明，按模板 key 输出 `{"sections": [...]}`。合并要点时合并编号（最多 4 个）；论文没涉及的小节输出空列表。
- 模板在 `core/prompts/templates/summary.yaml`，每个模板有版本号，写进 `prompt_version`。
- Map 提示词与模板无关，所以同一篇论文换模板时 Map 调用全部命中 `llm_cache`，这就是"分层"带来的复用。

### 校验（`domain/summary/citations.py`）

- 规范化：`b_12`、`B_0012`、`b-12`、`d_…#b_0012`，以及写在正文里的 `[b_0012]` / `（b_1, b_2）`，都统一成 `b_NNNN`，并从正文里去掉。
- Map 阶段只接受本组的块，Reduce 阶段接受全文的块；不在范围内的编号丢弃，计入 `invalid_ids`。
- 没有有效引用的要点标 `untraced`，界面显示"未溯源"。
- 模型回复不是 JSON 时（常见于带了说明文字或 ``` 代码块），先从回复里取第一个完整的 JSON 对象；仍失败就不走缓存重试一次。Map 失败的组跳过并记在 `failed_groups`；全部失败或 Reduce 失败时报错。
- Reduce 把小节名写进 key、或者没写 key 时，按名称或位置对应到模板小节。

### 重新解析

块 ID 在重新解析后可能变化（快速模式 → MinerU）。`ParseService._store` 用迁移译文时的同一份块映射（IR §8）改写总结引用。有引用映射不上时，这条引用被去掉，总结标 `stale`，面板提示"原文已重新解析，可以重新生成"。

### 接口

- `GET /summary/templates`
- `GET /documents/{doc_id}/summaries?lang=`：已有总结，新的在前，离线可读。
- `POST /documents/{doc_id}/summary {template_id, lang?}`：SSE 事件依次为：
  - `progress {stage: map|reduce, done, total, title}`
  - `summary {SummaryOut}`
  - 出错时 `error {code, message, provider_id}`，code 为 `consent_required`、`route_not_configured`、`missing_api_key`、`unknown_template`、`llm_error` 或 `bad_output`
  - 最后 `done`

  面板关闭时请求中止，服务端取消未完成的调用；已完成的 Map 结果在缓存里，下次很快。

## 评测

验收标准是"评测集上总结的引用覆盖率 ≥ 90%"。

- 引用覆盖率 = 有有效引用的要点 / 全部要点（`freeread/eval/summary.py`）。
- 引用有效率 = 有效编号 / 模型给出的全部编号。
- 忠实度（引用的块是否真的支持这条结论）无法自动判断：脚本为每篇生成一份对照稿，把每条要点和它引用的原文并排列出，供人工抽检（PRD 目标为忠实度 ≥ 95%）。

```bash
cd core
# 真实模型（OpenAI 兼容接口），Key 从环境变量读取；--record 录下回复，之后可用 --replay 免费重跑
set FREEREAD_EVAL_API_KEY=sk-...
.venv/Scripts/python ../scripts/m2_summary_eval.py --base-url https://api.deepseek.com/v1 --model deepseek-chat --record ../eval-out/m2-summary/replies.json
# 只验证链路
.venv/Scripts/python ../scripts/m2_summary_eval.py --fake --limit 4
```

输出在 `eval-out/m2-summary/`：`report.md`（汇总表）、`<doc_id>.json`（总结与统计）、`<doc_id>.md`（人工抽检对照稿）。

**加快评测**：第一次跑 31 篇是串行的，约 38 分钟。从 `llm_calls` 看，时间几乎全在模型生成上：Map 每次中位数 12 s、Reduce 34 s。deepseek-flash 是推理模型，输出 token 里约六成是"思考"（Map 回复约 1400 字，却用了 2445 个输出 token）。

- `--jobs N`：同时总结 N 篇（默认 4），并把总结服务的全局 Map 并发放大到 N × 3（`--map-concurrency` 可改）。本地 mock 每次调用 5 s 时，8 篇从 176 s 降到 42 s（4.2 倍），据此估计真实评测约 10 分钟。服务商限流（429）时调小 N；网关会自动退避重试。
- `--extra-body '<JSON>'`：透传服务商参数，比如关闭推理模型的思考。参数名因服务商而异，请查对应文档。关闭后模型行为会变，引用覆盖率和忠实度需要重新看。这些参数会进入缓存键，不会和开着思考时的结果混在一起。
- 中断后重跑：相同输入的调用会命中数据目录里的缓存，只补没完成的部分。

### 结果

| 运行 | 文档 | 引用覆盖率 | 引用有效率 | 备注 |
|---|---|---|---|---|
| `--fake`（确定性假模型） | 4 篇 | 100%（170 / 170） | 100% | 只证明链路正确：假模型每条都按输入编号引用 |
| deepseek-flash，第一次（2026-10-19，用户运行） | 29 / 31 篇 | 100%（950 / 950） | 100%（1998 / 1998） | 有一篇 0 个要点，见下文 |
| 同上，修复后用录下的回复重放 | 29 / 31 篇 | **100%（984 / 984）** | **100%（2079 / 2079）** | 0 要点那篇救回 34 条 |
| deepseek-flash，第二次（排除页面装饰块后、`--jobs 4`，用户运行） | 29 / 31 篇 | 99.7%（957 / 960） | 100%（1976 / 1976） | codonGPT 只剩 3 条以编号为正文的要点，见下文 |
| 同上，修复解析后用缓存离线重算 | 29 / 31 篇 | **100%（1004 / 1004）** | **100%（2096 / 2096）** | codonGPT 恢复 47 条；缓存里 61 条汇总回复全部能严格解析 |

- 失败的两篇（`d_27e305b3be5ac1bf`、`d_c7ac15aa1be2372c`）是评测集里的合成扫描件，没有文字层，PyMuPDF 快速解析得不到正文，报"文档里没有可总结的正文"。这是预期行为，OCR 不在本项范围内。
- 模型几乎从不省略引用，所以覆盖率达到 100%。真正需要关注的是引用对不对（忠实度），见下文抽检。
- 每篇 7–15 次调用（章节组中位数 8 组，再加一次 Reduce）。耗时 46–155 s，中位数 73 s，6 / 29 篇在 60 s 内。第一次运行的完整报告在 `eval-out/m2-summary/report-run1.md`（不入库）。

**第一次运行发现的 bug**（已修）：`d_be31326296626169` 的 8 个章节组都成功了，但 Reduce 回复的 JSON 结构是坏的：其他小节被写成第一个小节对象里的键（`{"key":"problem","points":[…],"method":[…]}`），外层括号也不配对。`extract_json` 退而取了内层对象，里面没有 `sections`，结果是 0 个要点，却被当成正常总结保存了。修复内容：
- Reduce 依次尝试回复里的每个 JSON 对象，并能识别"小节对象里混入其他小节"、"sections 写成 {key: points}" 这几种形状；
- 整理不出任何要点时按解析失败处理，不走缓存重试一次；仍失败就报 `bad_output`，不保存空总结；
- Map 只接受含 `points` 的对象。

`test_summary.py` 用这条真实回复的形状加了回归测试。

**第二次运行发现的问题**（已修）：上面的兜底太宽了。`d_2ca951d5e87040a4`（codonGPT）的汇总回复里，每个小节结尾都多写了下一个小节的 key（`…],"method"},{"key":"method",…`）。兜底依次尝试回复里的 JSON 对象，结果取到了一个要点对象 `{"text":…,"block_ids":[…]}`，把 `block_ids` 当成小节，于是块编号变成了要点正文（3 条，覆盖率 0%）。另一篇 `d_2d8e7b5188a46ca6` 的回复结尾少了 `]}`，之前靠兜底只取回了部分结构。现在的做法：
- 解析前做轻量修复：删掉对象末尾没有冒号的孤立字符串，补齐结尾缺的右括号；修复后仍要能被 `json.loads` 解析才采用。缓存里全部 61 条汇总回复都能这样严格解析。
- 严格解析：要求有 `sections` 且至少一个要点；失败就不走缓存重试一次。两次都失败才兜底，兜底只认 `{key, points}` 形状的小节对象，以及键名是模板小节的对象；用了兜底的结果在 `stats.salvaged` 标出。
- 只有块编号、没有内容的要点直接丢弃。

### 忠实度抽检（初步）

我从 29 篇的对照稿里随机抽了 15 条要点，对照引用的原文判断。这不能代替正式的人工抽检：

| 结果 | 条数 | 说明 |
|---|---|---|
| 支持 | 11 | 数值、方法名、结论都能在引用块里找到 |
| 部分支持 | 2 | 引用块只覆盖要点的一部分（如 Fig. 6 图注只列出了几种情形，"最简约"的判断不在图注里） |
| 不支持 | 2 | ① 引用了页眉（"Grubert et al., 2015, Cell 162…"）；② 引用的段落与要点相邻，但要点里的数字（adj r² = 0.74）不在其中 |

PRD 的目标是忠实度 ≥ 95%。初步看还有差距，主要有两类错误：
- PyMuPDF 快速模式把页眉页脚当成正文块，模型会引用它们。可以在送给 Map 之前过滤页面装饰块，或者改用高质量解析的 IR。
- 要点合并了相邻段落的内容，但只引用了其中一段。

正式的人工抽检用 `eval-out/m2-summary/<doc_id>.md` 对照稿进行。

## 验证

- `core`：184 个测试通过。`tests/test_summary.py` 新增 12 个，覆盖：
  - 分组：按根章节分组、标题前单独成组、合并 / 切开、参考文献排除；

  - 服务：Map 每组一次、Reduce 一次，换模板命中缓存，同一模板替换旧结果；
  - 回退到翻译路由，隐私确认，JSON 错误重试，小节名对应；

  - API 和评测函数。

  `test_llm_gateway` 原来"总结未配置就报错"的断言改为不回退的 `kg_extract`，另加回退测试。翻译的测试没改，确认抽出共用 preflight 后行为不变。

- 浏览器模式（开发版 sidecar、Vite、本地 OpenAI 兼容 mock，mock 用 `summary_responder` 回 JSON），在评测集的 mRNA 论文上：

  - 控制台没有错误。
