# M2-4：术语表与整篇后台翻译

- 日期：2026-10-20
- 关联：[路线图 M2](../04-roadmap.md)、[架构 §5.5](../01-architecture.md)、[数据模型 glossary_terms](../03-data-model.md)

## 结论速览

| 项目 | 结果 |
|---|---|
| 术语来源 | 用户手动添加 / 编辑；或让模型从论文中自动抽取（任务 `glossary_extract`，一次调用） |
| 范围 | 全局条目对所有文档生效；文档条目只对该文档生效，并覆盖全局同名条目；文档条目可"提升为全局" |
| 注入方式 | 翻译每个块时只带上在该块里出现的条目（最多 24 条，长术语在前） |
| 整篇翻译 | 阅读器"翻译全文"排队任务 `translate_doc`，跳过已译的块，每批 30 块，进度在任务栏，译文边翻边显示 |
| 自动抽取 + 翻译 | 设置 › 术语表 › "翻译全文前自动抽取术语"（默认关）：文档还没有自动术语时，翻译任务等抽取任务完成再开始 |
| 隐私 | 抽取和翻译一样，首次发送前需要确认；路由 `glossary` 未单独配置时沿用翻译的服务 |

## 设计

### 术语匹配（`services/glossary.py`）

- 拉丁文字的术语按词边界匹配，不区分大小写，允许复数 `s` / `es`（`codon` 命中 `Codons`，不命中 `anticodonal`）；多词术语中间的空白可以是任意空白。
- 含其他文字（中日韩、希腊字母等）的术语按子串匹配。
- 每个文档、每种目标语言的条目编译一次后缓存，任何增删改后整体失效。

### 提示词

`translate.yaml` 原本就有可选的 `glossary` 块（`- source → target`），这次只是开始传入，不改模板、不升版本。缓存键由渲染后的消息决定，所以改了术语后同一段落不会命中旧缓存；已经存下的译文不会自动更新（面板底部有提示）。

`glossary_extract@1`：输入标题、摘要、章节标题和正文（约 12000 字符，摘要和标题优先，正文取 40 字符以上的块），要求输出 `{"terms": [{source, target, note}]}`。专有名称、模型名、基因名等通常保持原文。JSON 解析复用总结的 `extract_json`，失败时不走缓存重试一次。

### 自动条目与用户条目

- 抽取结果写成文档条目，`origin=auto`；重新抽取先删掉该文档的 auto 条目再写入。
- 与已有用户条目（文档或全局）同名的不写入。
- 用户编辑过的条目（哪怕只改了说明）变成 `origin=user`，以后重新抽取不再覆盖。

### 整篇翻译（`TranslateService.run_doc_job`）

- 取所有可翻译、非空、还没有有效译文的块，按阅读顺序每 30 块调用一次 `translate_blocks`。和阅读器的可视区域请求共用全局并发（3）和"同一块只翻一次"的去重，用户边读边翻也不会重复调用。
- 每批结束报告进度；前端看到任务进度变化就重新拉一次 `/translations` 合并进来。
- 结束信息：`翻译 N 段`，有需要复核或失败的段落时附上数量；全部失败时任务失败。
- 文档语言与目标语言相同时直接完成。

### 接口

- `GET /glossary?lang=&doc_id=`：不给 `doc_id` 只列全局条目，给了列全局 + 该文档条目。
- `POST /glossary {source, target, note?, doc_id?, lang?}` → 201；同一范围、同一语言重名 → 409。
- `PATCH /glossary/{id} {source?, target?, note?, scope?: "global"}`；`DELETE /glossary/{id}` → 204。
- `POST /documents/{doc_id}/glossary/extract {lang?}` → 202 `JobOut`。
- `POST /documents/{doc_id}/translate {lang?}` → 202 `JobOut`。
- 模型不可用时两个任务接口都返回 409，`detail = {code, message, provider_id}`（`route_not_configured` / `missing_api_key` / `consent_required`），前端据此弹出隐私确认框，确认后自动重试。

另外 `JobQueue.find_active(kind, **payload)` 用于按 payload 字段去重（同一文档、同一语言的任务只排一个）。

## 验证

- `core`：240 个测试通过，新增 `tests/test_glossary.py` 8 个：
  - 匹配规则（词边界、复数、多词、中文、希腊字母）；
  - 增删改与全局 / 语言隔离；
  - 抽取任务（去重、不覆盖用户条目、重新抽取只替换 auto、编辑后变 user、提升为全局）；
  - 翻译只注入命中的条目，改术语后不命中旧缓存；
  - 整篇翻译跳过已译块、调用次数正确；
  - 自动抽取依赖、隐私确认、API 状态码。
- 前端：`tsc`、`vitest` 通过。
- 浏览器模式（开发版 sidecar、Vite、本地 OpenAI 兼容 mock；mock 把提示词里的术语在译文中标成〔译法〕），在评测集的群体表观基因组论文上：
  - 打开术语面板 → 自动抽取，5 条术语出现，标"自动"；
  - 手动添加 `methylation → 甲基化`；
  - 点"翻译全文"，任务栏显示 `翻译全文：0 / 88 段` 到完成，按钮显示进度并禁用，结束信息 `翻译 88 段`；
  - 新译文里出现〔甲基化〕，说明只在含该词的段落里注入了术语；
  - 设置 › 术语表显示开关和全局术语列表。

## 遗留

- [ ] 改了术语后已有译文不会更新。可以加"按新术语重新翻译含该术语的段落"（按 `terms_for_block` 找出受影响的块，删掉译文后重新排队）。
- [ ] 分类级术语表（`scope=collection:<id>`）。
- [ ] 抽取只看前约 12000 字符，超长论文后半部分的术语可能漏掉；可以按章节分批抽取再合并。
- [ ] 用真实模型评估抽取质量和注入后的译文一致性。
