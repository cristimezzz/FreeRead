FreeRead 0.2.4：修复 macOS 版全新安装后无法启动的问题。

## 下载

| 文件 | 说明 |
|---|---|
| `FreeRead_0.2.4_x64-setup.exe` | Windows 安装包（推荐）。安装到当前用户目录，不需要管理员权限；缺少 WebView2 时会自动安装 |
| `FreeRead_0.2.4_x64-portable.zip` | Windows 便携版。解压后运行 `freeread-desktop.exe`；需要系统已有 WebView2（Windows 10/11 一般自带） |
| `FreeRead_0.2.4_aarch64.dmg` | macOS（Apple 芯片）。打开后把 FreeRead 拖进"应用程序" |
| `FreeRead_0.2.4_amd64.AppImage` | Linux 任意发行版，免安装。`chmod +x` 后直接运行，需要 FUSE 2（Ubuntu 上是 `libfuse2` / `libfuse2t64`） |
| `FreeRead_0.2.4_amd64.deb` | Debian、Ubuntu 及其衍生版：`sudo apt install ./FreeRead_0.2.4_amd64.deb` |
| `FreeRead-0.2.4-1.x86_64.rpm` | Fedora、openSUSE 等：`sudo dnf install ./FreeRead-0.2.4-1.x86_64.rpm` |

Arch 等其他发行版用 AppImage。

- Windows 10/11 x64。安装包和程序**没有代码签名**，首次运行时 SmartScreen 可能提示"Windows 已保护你的电脑"，点"更多信息 → 仍要运行"即可。
- macOS 14 以上，Apple 芯片（M1 及更新）；暂不提供 Intel 版。**未经 Apple 公证**，第一次打开时在 Finder 里右键 FreeRead › **打开**，再在弹窗里点 **打开**；没有"打开"按钮时到"系统设置 › 隐私与安全性"底部点 **仍要打开**。
- Linux x86_64，需要 glibc 2.35 以上（Ubuntu 22.04、Debian 12、Fedora 36 及更新）和 WebKitGTK 4.1。

详见 [安装](https://docs.freeread.work/install)。

## 从 0.2.3 升级

- **macOS**：0.2.3 无法正常使用，不用等应用内更新，直接下载 `FreeRead_0.2.4_aarch64.dmg`，把 FreeRead 拖进"应用程序"替换旧版即可。
- **Windows、Linux**：在 **设置 › 关于** 里点"检查更新"：Windows 安装版下载后自动安装并重新打开；便携版、AppImage、deb、rpm 下载到"下载"文件夹，由你替换或安装。
- 文献库、设置和 API Key 都保留。

## 修复

- **macOS 版无法启动**：0.2.3 的 dmg 打包时用了不支持 SQLite 扩展的 Python，后台服务一连数据库就退出，报 `'sqlite3.Connection' object has no attribute 'enable_load_extension'`。现在打包固定使用支持扩展的 Python，并在打包时检查；发布前的安装包冒烟测试失败时也会让构建失败，不再被漏掉。

## 其他

- 去掉 AUR 支持：`freeread-bin` 一直没有成功上架 AUR，Arch 等其他发行版改用 AppImage。在 Arch 上装了 deb 的，检查更新时按 deb 下载到"下载"文件夹。
- 项目主页按访客的系统推荐对应的安装包（Windows / macOS / Linux）；手机和平板上提示到电脑上下载。

## 已知限制

- Windows 程序未签名，macOS 程序未经公证。Linux 只有 x86_64，没有 ARM 版；macOS 没有 Intel 版。AppImage 不会自动加入应用菜单。
- 知识图谱是单篇的，实体不跨文献合并；跨文献问答和文献引用图（M3 后续）尚未完成。
- MinerU / Docling 本机安装需要下载数 GB；没有 GPU 时建议用快速模式或远程服务。
